# 할 일 앱

한 화면에서 할 일을 적고, 끝낸 것을 표시하고, 지우고, 고칠 수 있다.
브라우저를 닫았다 다시 열어도 목록은 그대로 남는다.

승인된 화면: [prototype.html](./prototype.html)

## 사용자에게 보이는 결과

1. 떠오른 할 일을 입력창에 적고 Enter 한 번으로 목록에 남긴다.
2. 끝낸 항목을 체크해서 남은 일과 끝낸 일을 구분한다.
3. 필요 없어진 항목을 목록에서 지운다.
4. 잘못 적었거나 내용이 바뀐 항목을 그 자리에서 고친다.
5. 페이지를 새로고침하거나 브라우저를 다시 열어도 목록이 그대로 있다.

## 승인된 범위

### 포함

- 할 일 추가 · 완료 표시 · 삭제 · 인라인 편집
- 목록 유지 (같은 브라우저에서 다시 열었을 때)
- 빈 목록 안내
- 단일 화면. 다른 화면으로 이동하는 경로 없음

### 제외 (그리고 이유)

| 제외 | 이유 |
|---|---|
| 인증 · 로그인 | 요청자가 범위에서 명시적으로 뺐다 |
| 서버 저장 · 기기 간 동기화 | 같은 이유. 저장은 브라우저 안에서만 일어난다 |
| 드래그 앤 드롭 정렬 | 같은 이유 |
| 카테고리 · 태그 | 같은 이유 |
| 필터 (전체 / 진행 중 / 완료) | 요구된 기능 목록에 없다. 완료 항목은 목록에 그대로 남아 구분만 된다 |
| 남은 개수 · 진행률 표시 | 같은 이유 |
| 전체 완료 · 완료 항목 일괄 삭제 | 같은 이유 |
| 마감일 · 알림 · 검색 · 정렬 | 같은 이유 |

## 관찰 가능한 인수 기준

### 추가

- 입력창에 글자를 적고 Enter를 누르면, 그 항목이 **목록 맨 위**에 나타난다.
- 추가 직후 입력창은 비고, 이어서 바로 다음 항목을 적을 수 있다.
- 앞뒤 공백은 다듬어 저장된다. `  장보기  `를 넣으면 `장보기`로 보인다.
- 공백만 있는 상태에서 Enter를 누르면 아무것도 추가되지 않고, 입력한 내용도 지워지지 않는다.
- 이미 있는 것과 같은 내용을 적어도 별개 항목으로 추가된다.

### 완료 표시

- 항목의 체크박스를 클릭하면 완료로 표시된다: 체크 표시가 채워지고, 글자에 취소선이 생기고, 색이 흐려진다.
- 다시 클릭하면 완료가 풀리고 원래 모습으로 돌아간다.
- 완료로 바뀌어도 **항목의 자리는 그대로다.** 아래로 내려가거나 목록에서 사라지지 않는다.

### 삭제

- 항목의 삭제 버튼을 클릭하면 그 항목이 즉시 목록에서 사라진다. 확인 절차는 없다.
- 삭제 버튼은 마우스를 올리지 않아도 항상 보인다.
- 다른 항목의 내용과 완료 상태는 영향받지 않는다.

### 인라인 편집

- 항목의 글자를 더블클릭하면 그 자리가 입력 가능한 상태로 바뀌고, 커서가 글자 **맨 끝**에 놓인다.
- Enter를 누르면 고친 내용이 저장되고 편집이 끝난다.
- Escape를 누르면 고친 내용이 버려지고 원래 내용이 그대로 남는다.
- 편집 중에 바깥을 클릭하면 고친 내용이 **저장된다.**
- 내용을 전부 지우고 저장하려 하면 저장되지 않고 **원래 내용이 유지된다.** 항목은 사라지지 않는다.
- 앞뒤 공백은 추가할 때와 같게 다듬어진다.
- 완료로 표시된 항목도 같은 방식으로 편집할 수 있고, 편집해도 완료 상태는 유지된다.
- 한 번에 한 항목만 편집 상태가 된다.

### 새로고침 후 유지

- 항목을 추가·완료·삭제·편집한 뒤 새로고침하면, 마지막 상태 그대로 보인다. 순서와 완료 여부가 모두 유지된다.
- 브라우저를 완전히 닫았다 같은 브라우저로 다시 열어도 마찬가지다.
- 새로고침 직후 저장된 목록이 바로 보인다. 빈 목록 안내가 잠깐 스쳤다가 항목으로 바뀌는 일이 없어야 한다.

### 빈 목록

- 항목이 하나도 없으면 "할 일이 없습니다"와 함께 무엇을 하면 되는지 안내가 보인다.
- 마지막 항목을 지우면 빈 목록 안내로 바뀐다.
- 빈 상태에서 항목을 추가하면 안내가 사라지고 목록이 보인다.

### 표시 전반

- 긴 내용과 공백 없는 긴 문자열(예: URL)도 줄바꿈되어 보인다. 화면이 가로로 밀리지 않는다.
- 좁은 화면(휴대폰 폭)에서도 같은 조작이 모두 가능하고 잘리는 요소가 없다.
- 체크박스·삭제 버튼·입력창은 키보드로 이동했을 때 어디에 있는지 보인다.

## 확정된 제약과 근거

- **저장은 브라우저 안에서만 한다.** 요청자가 서버 저장을 범위에서 뺐고, 요구사항에 localStorage를 지목했다. 계정도 서버도 없으므로 같은 브라우저·같은 기기에서만 목록이 이어진다.
- **사용자에게 보이는 말은 한국어로 쓴다.** 화면 제목은 "할 일"이다. 저장소의 언어 규칙(`AGENTS.md`)을 따른다.
- **화면은 하나다.** 목록이 곧 앱 전체다. 네비게이션·라우팅이 필요한 구조를 만들지 않는다.
- **완료는 상태 표시일 뿐 분류가 아니다.** 완료해도 목록에서 빠지거나 자리를 옮기지 않는다. 필터가 범위 밖이라, 완료 항목이 사라지면 다시 찾을 방법이 없기 때문이다.
- **화면의 생김새는 프로토타입이 기준이다.** 프로토타입은 프로젝트의 기존 디자인 토큰(`app/globals.css`의 `:root`)을 그대로 옮겨 만들었다. 단, 프로토타입은 네트워크 의존을 두지 않으려고 시스템 폰트로 대체했으므로, 실제 화면의 글꼴은 프로젝트 설정을 따르고 자간·행높이가 조금 다를 수 있다.

## 가정 (되돌릴 수 있음)

확정한 사람은 에이전트다. 어긋나면 눈에 바로 띄고 바꾸기도 쉬운 것들이라 질문 없이 정했다.
바꾸고 싶으면 이 문서를 고치면 되고, 인수 기준의 해당 항목이 함께 바뀐다.

| 가정 | 정한 값 | 뒤집었을 때 |
|---|---|---|
| 공백만 입력 후 Enter | 추가하지 않고 입력값도 지우지 않는다 | 입력값을 지우거나, 빈 항목을 만든다 |
| 편집 중 내용을 다 지우고 저장 | 저장하지 않고 원래 내용을 유지한다 | 항목을 삭제한다 (TodoMVC 방식) |
| 편집 중 포커스 이탈 | 저장한다 | 취소하거나, 편집 상태를 유지한다 |
| 편집 시작 시 커서 | 글자 맨 끝 | 전체 선택 |
| 완료된 항목 편집 | 가능 | 완료를 풀어야 편집 가능 |
| 삭제 | 확인 없이 즉시 | 확인 절차나 되돌리기를 둔다 |
| 삭제 버튼 노출 | 항상 보인다 | 마우스를 올렸을 때만 보인다 |
| 같은 내용 중복 추가 | 허용한다 | 막거나 경고한다 |
| 저장이 막히거나 저장된 값이 깨졌을 때 | 화면 조작은 그대로 되고, 별도 오류 안내는 두지 않는다. 깨진 값은 빈 목록으로 시작한다 | 사용자에게 저장 실패를 알린다 |

## 유보한 결정

- **여러 탭을 동시에 열었을 때의 동기화.** 요구사항에 없어 이번 범위에서 다루지 않는다. 한 탭에서 바꾼 내용이 다른 탭에 자동으로 반영되지 않는다.
- **저장 용량 한계 처리.** 항목이 아주 많아져 저장이 막히는 경우의 사용자 경험을 정하지 않았다.
- **다크 모드.** 프로젝트에 다크 토큰이 정의되어 있지만 요구사항에 없어 이번 범위에서 판단하지 않았다.

## 남은 위험

- **여러 탭에서 함께 쓰면 작업이 사라질 수 있다.** 두 탭이 각자 목록을 들고 있다가 나중에 저장한 쪽이 앞 탭의 변경을 덮어쓴다. 위 "유보한 결정"을 되짚어야 해결된다.
- **저장 실패를 사용자가 모른 채 지나갈 수 있다.** 사생활 보호 모드나 저장 차단 환경에서는 조작이 되는 것처럼 보이다가 새로고침 후 사라진다. 오류 안내를 두지 않기로 한 가정의 대가다.
- **브라우저 데이터를 지우면 목록이 사라진다.** 서버 저장이 범위 밖이라 백업 경로가 없다. 사용자가 이 성격을 이해하고 쓰는 것을 전제한다.
- **프로토타입의 글꼴이 실제 화면과 다르다.** 줄바꿈 위치와 세로 여백이 프로토타입과 미세하게 달라질 수 있으므로, 구현 후 실제 화면에서 긴 내용과 좁은 폭을 다시 확인해야 한다.
