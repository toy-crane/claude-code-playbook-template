# Todo 앱 스펙

## 사용자에게 보이는 결과
- 사용자는 입력창에 할 일을 입력하고 Enter를 눌러 새 Todo를 추가할 수 있다. 새 Todo는 항상 목록 맨 위에 나타난다.
- 사용자는 각 Todo의 체크박스를 클릭해 완료 여부를 표시할 수 있다. 완료된 Todo는 시각적으로 구분된다(취소선 등).
- 사용자는 각 Todo의 삭제 버튼을 클릭해 해당 항목을 즉시 목록에서 제거할 수 있다.
- 사용자는 Todo 텍스트를 더블클릭해 인라인으로 내용을 수정할 수 있다.
- 사용자가 브라우저를 새로고침해도 Todo 목록(텍스트, 완료 상태, 순서)이 그대로 유지된다.

## 승인된 범위
- 단일 사용자, 단일 브라우저 기준의 Todo 목록 CRUD (추가 / 완료 토글 / 삭제 / 텍스트 수정)
- localStorage를 이용한 클라이언트 사이드 영속성
- 인증/로그인 없음
- 서버 저장/동기화 없음
- 드래그 앤 드롭을 통한 순서 변경 없음
- 카테고리/태그 없음

## 관찰 가능한 수용 기준
1. 입력창에 텍스트를 입력하고 Enter를 누르면, 새 Todo가 목록의 첫 번째 항목으로 나타난다.
2. 입력값이 비어있거나 공백만 있는 경우 Enter를 눌러도 새 Todo가 추가되지 않는다.
3. Todo를 추가한 뒤 입력창은 비워져 다음 입력을 받을 준비가 된다.
4. 미완료 Todo의 체크박스를 클릭하면 완료 상태로 전환되고 완료 표시(취소선 등)가 나타난다. 다시 클릭하면 미완료로 되돌아간다.
5. Todo의 삭제 버튼을 클릭하면 해당 항목이 목록에서 즉시 사라지고, 다른 항목의 순서는 유지된다.
6. Todo 텍스트를 더블클릭하면 해당 항목이 편집 가능한 입력 필드로 바뀐다.
7. 편집 중 Enter를 누르거나 입력 필드 밖을 클릭(blur)하면 변경된 텍스트가 저장되고 편집 모드가 종료된다.
8. 편집 중 Escape를 누르면 변경 사항을 버리고 원래 텍스트로 되돌아가며 편집 모드가 종료된다.
9. 편집 결과가 비어있거나 공백만 있는 경우, 텍스트는 원래 값으로 유지된다 (편집으로 인한 삭제는 없음).
10. 한 번에 하나의 Todo만 편집 모드로 전환된다.
11. Todo를 추가/완료 토글/삭제/수정한 직후 페이지를 새로고침하면, 새로고침 전의 목록 상태(텍스트, 완료 여부, 순서)가 그대로 복원된다.
12. Todo가 하나도 없을 때는 목록 대신 빈 상태 안내가 표시된다.
13. localStorage에 저장된 데이터를 읽을 수 없거나 손상된 경우, 빈 Todo 목록으로 시작한다 (오류로 앱이 멈추지 않는다).

## 확정된 제약과 근거
- 저장소는 브라우저 localStorage로 한정한다 — 요구사항에서 서버 저장을 명시적으로 배제했고, 인증이 없어 사용자를 식별할 방법이 없다.
- 새 Todo는 항상 목록 맨 위에 추가된다 — 요구사항 1번에서 명시.
- 드래그 앤 드롭, 카테고리/태그, 인증은 만들지 않는다 — 요구사항의 범위 제한에서 명시적으로 배제.

## 가정 (재검토 가능)
- 완료 상태 토글이나 텍스트 수정으로 항목의 목록 내 순서는 바뀌지 않는다 (완료된 항목이 하단으로 이동하지 않음).
- 인라인 편집 중 blur(포커스 이탈)는 Enter와 동일하게 "저장"으로 취급한다.
- 삭제는 확인 대화상자 없이 즉시 실행된다.
- 목록이 비어 있을 때는 간단한 안내 문구를 보여준다 (별도 일러스트 등은 없음).
- 항목별 필터(전체/진행중/완료)나 남은 항목 개수 표시는 요구사항에 없으므로 만들지 않는다.

## 범위 밖 영역과 이유
- 다중 탭/다중 기기 간 실시간 동기화: localStorage는 브라우저-로컬 저장소이고 서버 저장이 범위 밖이므로 동기화 메커니즘은 만들지 않는다.
- 실행 취소(undo) 기능: 요구사항에 없는, 범위를 벗어난 추가 기능이다.

## 유예된 사항
- 없음 — 구현에 필요한 모든 동작이 이번 스펙에서 확정되었다.

## 남은 위험
- localStorage 용량 제한(브라우저별로 다름)을 초과할 정도로 Todo가 많아지는 극단적 사례는 다루지 않는다. 실사용에서 발생 가능성은 낮다고 판단한다.
- localStorage가 비활성화된 환경(프라이빗 모드 등)에서는 새로고침 시 데이터가 유지되지 않을 수 있다. 이는 브라우저 정책에 따른 제약이며 이번 스펙의 대응 범위 밖이다.
